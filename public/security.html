Security

Architecture

Visitor Recognizer is a single Node.js service hosted on Render in the United States, with a Postgres database hosted by Neon on AWS us-east-2 (United States), connected over TLS. It connects to Ring only through Ring's official Partner API (oauth.ring.com and api.amazonvision.com) using each customer's own authorization. Face detection and matching run inside the service; no external face-recognition API is used.

Protections

  • TLS for all traffic; HSTS.
  • AES-256-GCM application-level encryption of all stored records, Ring tokens, face templates and snapshots, with the key held only in the server environment.
  • Passwords hashed with scrypt; HttpOnly, Secure, SameSite session cookies; CSRF tokens on every form and change; sign-in rate limiting.
  • Every record is owned by one customer account and every request is checked against it. There is no cross-account matching or sharing.
  • Ring webhooks verified with HMAC-SHA256 signatures; account linking verified with Ring's HMAC nonce, only after you sign in.
  • Strict Content-Security-Policy and no third-party scripts.
  • Automated dependency auditing and tests on every change; Dependabot updates.
  • Operator access is limited to the service owner; there is no staff tool to view customer snapshots or templates.

Reporting a vulnerability

Email mussadrammeh@protonmail.com with “Security” in the subject. We acknowledge within 3 business days and aim to fix critical issues within 7 days. Please don't access other people's data while testing.

Incident response

If we learn of unauthorized access to customer data we will contain it, rotate affected keys and tokens, notify affected customers and Ring without undue delay and within 72 hours of confirming it, and notify authorities where the law requires.
